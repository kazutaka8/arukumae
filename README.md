# アルクマエ

**現地を歩く前に、軌跡図にかかる筆と木を洗い出す道具。**

風車のブレードのような長い荷物を運ぶ前、用地の担当者は「どの土地（筆）にかかるか」「どの木を切ることになるか」を調べます。従来は公図を1件ずつ買い、座標のない公図を CAD で手で合わせ、紙の航空写真を持って現地を歩いていました。アルクマエは、無料で公開された公図・航空写真・森林のデータと軌跡図を1枚の地図に重ね、かかる筆を計算で拾い、木の有無を Claude が航空写真から区切りごとに判定します。人が確かめて直し、最後に「道路名と KP 付きの一覧表」と「現地に持って歩く地図」を出します。

**AI は候補を出し、人が確かめて決める。** この分担を道具の作りそのものにしています。

Built with Claude: Japan 2026 に向けて、2026年11月2日から作っています。

## いまできること（雛形）

- 長野県小川村 県道401号の見本で、公図（2,135筆）・航空写真・森林計画の対象森林・輸送路の中心線を重ねて見る
- **架空の軌跡図を車両の寸法から作る。** ブレードの長さと台車の寸法を入れると、追従の計算で掃く範囲を出し、地図に重ねる。
  型は「ブレードリフター（公道）」「伸縮トレーラー（公道。水平）」。既定は寝かせたまま（安全側）で、**立てられる場所と角度は区間ごとに人が決める**（電線をくぐる所では立てられないため）。KML・GeoJSON に保存でき、ほかの地図ソフトで開ける
- 軌跡図のファイル（KML・KMZ・GeoJSON）を落として読む。線でも多角形でも、中心線に投影して同じ形にする。座標は端末の外へ出さない
- 伐採範囲（掃く範囲＋余裕幅＋3m）にかかる筆を計算で拾い、一覧と地図で行き来する（既定の車両で 329筆。かかる部分だけを黄色に塗る）
- 区切り（10m ごと×左右、290）を、自分の API キーで Claude に判定させる。Sonnet 5.5 が全部を見て、確信の低い区切りだけ Fable 5.1 が見直す。
  押す前に費用の目安が出る（約 $0.6）。判定はこの端末（localStorage）に残る。見本として 80 区切りの判定が最初から入っている
- 判定を人が直す。直した区切りは「人」と記録され、地図では青い枠になる。元に戻せる
- 読んだ距離標を 2 本以上地図に置くと、全区切り・全筆に「小川長野線 ○.○○km 付近（推定）」と根拠（補間・外挿）が付く
- 一覧表を CSV（UTF-8 BOM。Excel でそのまま開ける）で書き出す：起点からの距離・左右・KP・所在・地番・かかる面積・木のある面積（推定）・樹種・確信・確かめる所・決めたのは
- **森林の区域（林野庁）を筆ごとに付ける。** ベクトルタイルを道具から直接読み、かかる部分が民有林・国有林の区域にどれだけ入るかを測る。民有林にかかる筆には「伐採の届出が要るかもしれない（市町村に確かめる）」の目印
- **持って歩く地図を PDF で書き出す。** A4 縦、索引図＋約 200m ずつのページ。航空写真の上に掃く範囲・筆と地番・区切りの判定・距離と KP を重ね、下に「現地で確かめる所」の表と○×・メモの欄
- **現地マップを KML・GeoJSON で書き出す。** かかる筆（かかる部分の形と吹き出し）・区切り（判定の色）・確かめる所の印・中心線と 100m ごとの点・距離標・伐採範囲の外側。iPad の Google Earth に入れると、現地を歩くときの地図になる（実務でやっていた形）
- **公図を買うリスト（CSV）。** かかる筆の所在・地番だけを並べた控え。登記情報提供サービスで 1 件ずつ取るときの、順と抜けの確認用
- 区切りの詳細に、**Claude が見た写真の切り抜き（札なし・札あり）** を出す。何を見て決めたかを人が確かめられる
- **持ち運びモード（現地の記録）。** 現地で区切りを見て ○（判定どおり）・△（分からない）・×（違う）とメモを残す。判定は変えず、記録として一覧表の列・現地マップの吹き出し（済んだ所は緑の印）・持って歩く地図の表に出る。× の所は帰ってから「この区切りを直す」で直す。記録はこの端末に残る
- **案件ファイル（JSON）で別の端末へ持ち出す。** 伐採範囲の決め方・読み込んだ公図の筆・判定・距離標・現地の記録・案件名を 1 つのファイルに保存し、iPad で読み込んで続きをする。現地で記録したら保存して PC に戻す。ファイルは手元に置くもので、道具が外へ送ることはない
- **一覧の絞り込み。** かかる筆は「木あり・確かめる所・森林の区域・未判定・現地 ×」と地番・所在の文字、確かめる所は「確信 低・森林・まだ・×・済」。地図は絞らず、手順 5 の前へ・次へは絞った中を回る
- 手順（案件 → 取り込み → かかる筆 → 木の判定 → 確かめて直す → KP → 書き出し）に沿ったパネル。一覧は「かかる筆」「確かめる所」のタブ。
  iPad の幅では、横向きは幅を詰め、縦向きは手順と一覧を下の引き出しにして地図を残す。地図に現在地のボタン

- 森林の区域と判定が食い違う区切り（区域なのに木が少ない、区域外なのに木が多い。縁から 15m は除く）を「確かめる所」に入れる。急カーブの内側で潰れる区切りは幅を抑え、小さいものは隣と合わせる

- **公図（地図XML）の zip をそのまま落として読む。** 法務省の市町村ごとの zip（中に地図ごとの zip と XML）を、展開せずにワーカーで流し読みし、区間の両側 200m の筆だけを残す。小川村（38MB、地図 28 枚、主の地図は展開すると 170MB）で約 7 秒。ファイルは端末の外へ出さず、読んだ筆はこの端末に残る。任意座標系の地図は読み飛ばして枚数だけ伝える

まだのもの：公図の位置合わせ（任意座標系の地図）。Claude に試した結果は [experiments/case_a/](experiments/case_a/) に（手がかりの 1 点は当てるが、基準点は人が打つのがよさそう）。

## 動かし方

```bash
cd app
npm install
npm run dev        # http://localhost:5173
npm test           # 座標の換算・区切り・追従の計算・軌跡図の読み書きの回帰テスト
npm run build      # dist/ に静的ファイル
```

見本のデータ（`data/ogawa/`）と試しの結果（`experiments/case_c/out/results/`）を読みます。

前処理と試しは Python です（`.venv` を作って `anthropic pillow numpy` を入れる）。公図の元データ（38MB の zip）は `data/raw/` に置き、リポジトリには入れていません。取り方は [data/README.md](data/README.md)。

## データの出典

- 公図：「登記所備付地図データ 上水内郡小川村」（法務省）（https://www.geospatial.jp/ckan/dataset/houmusyouchizu-2026-1-995）（2026年11月2日に利用）を加工して作成
- 航空写真：国土地理院（地理院タイル 全国最新写真）を加工
- 森林の区域：森林計画対象森林レイヤ（林野庁）（https://www.geospatial.jp/ckan/dataset/layer）。テストに同梱したタイル 1 枚（`app/src/core/fixtures/`）も同じ出典
- 道路の線：© OpenStreetMap contributors（ODbL）
- 区間の線とデモの軌跡図は、期間中にこのリポジトリの道具で作った架空のもの。実在の輸送計画ではありません

## Claude をどう使ったか

- **道具の中：** 区切りごとの航空写真を Claude Sonnet 5.5 に見せ、木の割合・樹種・確信・理由を決まった形の JSON で返させる。迷う区切りだけ上位モデルで見直す。送るのは公開データの画像だけで、軌跡図の座標・地名・案件名は送らない
- **作り方：** 仕様（docs/spec.md）→ 実装 → 回帰テスト → レビューの順で、コードは Claude Code が書いた。期間前の構想はリポジトリの外に置き、文書もデータも期間中に新しく作った

## 法令にふれることについて

伐採の届出などの要否は、この道具が決めるものではありません。目安を出すだけで、所管の市町村などに確かめてください。公図は法務局が「おおよその位置と隣接関係を示すもの」と説明している図面で、境界を証明するものではありません。
