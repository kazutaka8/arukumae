# 車載動画から障害物を拾う（検討メモ。2026-11-03）

輸送路を走った車載動画（ドライブレコーダー・スマホ）を道具に取り込み、航空写真では見えないもの（横断する電線、道路に張り出す枝、標識、電柱、橋の桁）を Claude に拾わせられるか。
**まだ作らない。** 実現できるか、どう作るべきかを先に詰める。

## 1. 何がうれしいか

航空写真は上から見るので、分かるのは「木がある・ない」まで。ブレードを運ぶ人が現地で見たいのは、むしろ横から見ないと分からないものが多い。

| 航空写真で分かる | 航空写真では分からず、車載動画なら分かる |
|---|---|
| 木の有無、おおよその樹種、畑・家 | **横断する電線**（立てられない所。§11.4 の起立の区間の根拠になる） |
| 森林の区域との重なり | **道路に張り出す枝**（伐採の対象になるか。真上からは樹冠が道路にかぶっているように見えても、高さがあれば問題ない） |
| 筆のおおよその位置 | 標識・電柱・カーブミラー・ガードレール・防護柵（撤去や移設の相談先が変わる） |
| | 橋の高欄・トンネル・民家の軒・擁壁の張り出し |
| | 路面（段差、路肩の弱さ）は見えるが、ここでは扱わない |

実務では、現地を歩いて見る前に車で一度走り、動画を見返して候補を出していた。それを道具の中でやる、という話。
ストリートビューは規約で画像の取り込みができない（spec §8.6）ので、**自分で撮った動画は、合法に「横から見る」唯一の道**でもある。

## 2. 論点は 2 つ

1. **動画のどの時刻が、中心線のどの位置か**（位置合わせ）
2. **1 コマを Claude に見せて、何がどこまで分かるか**（判定）

## 3. 位置合わせ

### 3.1 結論：GPS があれば簡単。無いときは「人が基準点を打つ」で足りる。カーブの形だけで合わせるのは、できるが精度は道次第

区切りは 10 m。10 m の精度で動画と地図を合わせたい。

| 手段 | 精度の目安 | 手間 | 評価 |
|---|---|---|---|
| **A. GPS の軌跡（GPX）を一緒に読む** | 3〜10 m。中心線に投影すれば区切りに落ちる | 撮るときに記録しておくだけ | **第一候補** |
| B. 動画に焼き込まれた速度（km/h）を OCR で読み、積分して距離にする | 速度の丸めで ±5% ほど。1.5 km で末尾 70 m ずれる。基準点を 300〜500 m ごとに打てば 10〜20 m | 焼き込みのあるドラレコだけ | GPS が取れないドラレコ動画の代わり |
| C. 人が基準点を打つ（交差点・橋・距離標の時刻と、地図の点を対にする。間は等速で補間） | 基準点の間隔と速度の変化しだい。カーブの多い道で 300 m ごとなら 10〜20 m | 1.5 km で 3〜5 か所 | **いつでも使える土台。** 距離標（F9）と同じ考え方・同じ画面でできる |
| D. 動画から進行方向の変化（ヨー角速度）を推定し、中心線の曲率の並びと DTW で合わせる | カーブの近くは良い。直線では決まらない（速度が分からないので、どこまで進んだか決められない） | 計算だけ。人手なし | 「スタートだけ分かっている」場合の最後の手。**C と組み合わせて補助に使う**のが現実的 |
| E. スマホのジャイロ・加速度のログ | D の入力として良い | GPS が取れる端末なら GPS を取ればよい | 使わない |

### 3.2 GPS の取り方（A）

- **スマホ：** 動画と同時に GPS を記録するアプリを使う（GPX が出るもの）。iPhone のカメラが書く位置情報は 1 本に 1 点だけと見ておく（コマごとの軌跡が入るという記述もあるが、Apple の文書で確かめていない）。動画の開始時刻（MP4 の作成日時）と GPX の時刻で合わせる
- **ドライブレコーダー：** GPS 付きの機種は動画の中か別のファイルに軌跡を持つ。形式はメーカーごとに違い、公開されていない。exiftool（`-ee`）が読める機種はある（Novatek 系、Viofo、Vantrue、Ambarella 系など。機種によって読めない）。国内メーカーは専用ビューワーで軌跡を出せる機種がある（ユピテルの ATLASTOUR は Google Earth 表示に対応）。**つまり「GPX か KML にして渡してもらう」を入口にし、ドラレコの独自形式は道具では読まない**
- 道具は GPX（と KML の LineString に時刻があるもの）を読み、各点を中心線に投影して「時刻 → 起点からの距離」の表を作る。あとは動画の時刻を引くだけ

### 3.3 人が基準点を打つ（C）

- 画面：動画を再生し、「いまの場所」を地図で押す（または距離標の値を入れる）。F9 の距離標と同じ UI で、動画の時刻が加わるだけ
- 2 点以上で、間を等速で補間。基準点が多いほど良い。カーブの前後で速度が変わるので、カーブの出入りに打つと精度が上がる
- D の曲率合わせは、基準点の間の「速度が変わる」ずれを補正する補助として後から足せる

### 3.4 カーブの形だけで合わせる（D）の中身

- 動画から：連続するコマのオプティカルフロー（または消失点の横ずれ）から、ヨー角速度 ω(t) を出す。路面の模様・白線・ガードレールが手がかり。夜間・雨・ワイパーで崩れる
- 地図から：中心線の曲率 κ(s)（spec §11.4 の curveFlags と同じ材料）
- ω(t) = κ(s(t))・v(t) なので、v(t) が分からないと s(t) は決まらない。**向きの変化の「順番と大きさ」だけを合わせる**（DTW）。カーブごとの対応は取れるが、直線区間の中の位置は等速の仮定で補うしかない
- 精度の見込み：カーブの多い山道で、カーブの近くは 10〜30 m、長い直線の途中は 50 m 以上ずれうる。10 m の区切りには足りない。**単独では使わず、C の補助**
- 作るなら Python で先に試す（experiments/）。動画 1 本と GPX（正解）があれば、ずれの分布が測れる

## 4. 判定（Claude に 1 コマ見せる）

### 4.1 できること・できないこと

| できる（見込み） | できない・あてにしない |
|---|---|
| 電線が道路を横断しているか、電柱・標識・ミラーがあるか、枝が道路の上に出ているか、橋・トンネルか | **高さや幅をメートルで言うこと。** 単眼の 1 コマから距離は出ない。「低い・高い」の目安まで |
| 左右どちらか（画面の左半分・右半分。横断するものは「上」） | 電線の種類（低圧・高圧）を確かに言うこと。電柱の形から推測はできるが、現地で確かめる |
| 理由を言葉で言う（「右から左へ電線が 2 本、電柱は右」） | 道路の幅員。白線がない道では出ない |

→ 出力は「**候補**」。木の判定と同じで、区切りごとに「横断する電線：あり／なし／分からない」「張り出す枝：あり／なし／分からない」「ほか：電柱・標識・ミラー・橋・…」「確信」「理由」を決まった JSON で返させ、人が確かめる。
電線ありの区切りは「起立できないかもしれない区間（候補）」として起立の区間（§11.4）の入力に、張り出す枝は「確かめる所」に入れる。

### 4.2 コマの取り方

- 区切り 10 m ごとに 1 コマ（40 km/h なら約 1 秒に 1 コマ）。1.45 km で 145 コマ。左右は同じコマで見る（前向きのカメラは両側が写る）
- 区切りの「手前」のコマを使う（その区切りに入る直前に、区切りの中の電線や枝が画面の上のほうに写る）。20 m 手前と 0 m のコマの 2 枚を見せると、横断するものが追える
- ブラウザの `<video>` と canvas で時刻を指定して描けば取れる。サーバー不要。MP4（H.264）はどのブラウザでも再生できる。iPhone の HEVC は Safari と Mac の Chrome は再生できるが、Windows の Chrome は端末しだい（「互換性優先」で撮ってもらう）
- 1 コマ 1280×720 で送る。費用は木の判定と同じ桁（Sonnet で 145 コマ、$0.5〜1 ほど。試して測る）

### 4.3 送るもの・送らないもの（§8.7 との関係）

- **動画は公開データではない。** 他人の車のナンバー、歩行者、民家が写る。いまの方針「Claude に送るのは公開データの画像だけ」の例外になる
- 入れるなら：(1) 使う人が自分で撮った動画に限る、(2) 送る前に「ナンバー・人が写る。Anthropic に画像が送られる」と明示して同意を取る、(3) 座標・時刻・地名は送らない（いままでどおり）、(4) 画面の下 1/4（自車のボンネットと近い車）を切る、(5) 動画そのものは端末の外へ出さない（コマだけ送る）
- 顔・ナンバーのぼかしを端末でかける手もあるが、ブラウザでの検出は重い。まずは (1)〜(5) で足りるか、使う人に聞く
- API に送った画像を学習に使わない契約かどうかは、Anthropic の利用規約で確かめる（自分の理解では、API の入力は既定で学習に使われない）

## 6. デモの舞台を変えるかどうか

動画を自分で撮れる地域に舞台を移す案について。

- 必要なもの：その道の公図（法務省の地図XML。市町村ごとに取れる）、中心線（OSM から `tools/make_section.py`）、森林の区域（全国のタイル）、動画と GPX。**データの段取りは小川村と同じ手順で 1 日**
- 捨てるもの：小川村の見本の判定（80 区切り、§15・§16 の試しの材料）。README・spec・demo.md の舞台の記述。公開済みの見本を差し替える作業
- 動画の撮影そのものは、提出までの残り日数では難しい（撮る人・行く日・天気）。**撮れた動画で段階 0 を試し、舞台を移すのは提出のあと**が現実的
- 実在の風力発電所に向かう道を選べば、輸送路の見本として説得力が増す。ただし「架空の輸送計画」と明記する（地権者の実在の情報を扱う道具なので）
- 公開物に出す地名は、作り手の身元の手がかりになる組み合わせを避ける（出身地の近くでも、実家のある町そのものは選ばない）
